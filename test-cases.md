TC-001 Авторизация пользователя с ролью “Администратор”

Модуль: Авторизация
Приоритет: Высокий
Тип тестирования: Функциональное / Role-based access

Предусловия:

* Пользователь зарегистрирован в системе.
* Учетная запись активна.
* Пользователю назначена роль “Администратор”.
* Сервис авторизации доступен.
* Пользователь не авторизован.

Тестовые данные:

* Логин: admin@test.ru
* Пароль: Admin123!

Шаги:

1. Открыть страницу авторизации.
2. Проверить наличие полей “Логин”, “Пароль” и кнопки “Войти”.
3. Ввести валидный логин администратора.
4. Ввести валидный пароль.
5. Нажать кнопку “Войти”.
6. Проверить HTTP-ответ запроса авторизации через DevTools.
7. Проверить наличие токена авторизации в Cookie или Local Storage.
8. Проверить переход в административную панель.
9. Проверить отображение разделов, доступных только роли “Администратор”.
10. Обновить страницу браузера.

Ожидаемый результат:

* Сервер возвращает 200 OK.
* Пользователь успешно авторизован.
* Создается пользовательская сессия.
* Токен авторизации сохранен.
* Открывается административная панель.
* Отображаются только разрешенные для администратора разделы.
* После обновления страницы пользователь остается авторизованным.

TC-002 Блокировка авторизации после нескольких неуспешных попыток входа

Модуль: Авторизация
Приоритет: Критический
Тип тестирования: Security / Negative

Предусловия:

* Пользователь зарегистрирован в системе.
* Учетная запись активна.
* Механизм ограничения попыток входа включен.

Тестовые данные:

* Логин: user@test.ru
* Неверный пароль: WrongPass123!

Шаги:

1. Открыть страницу авторизации.
2. Ввести валидный логин.
3. Ввести неверный пароль.
4. Нажать кнопку “Войти”.
5. Повторить попытку входа с неверным паролем 5 раз.
6. Проверить сообщение системы после превышения лимита попыток.
7. Проверить HTTP-ответ последнего запроса.
8. Попробовать выполнить вход с корректным паролем сразу после блокировки.

Ожидаемый результат:

* Система не выполняет авторизацию при неверном пароле.
* После превышения лимита попыток вход временно ограничивается.
* Пользователь видит сообщение о временной блокировке или необходимости повторить попытку позже.
* Сервер возвращает соответствующий код ошибки, например 429 Too Many Requests или 403 Forbidden.
* Вход с корректным паролем временно недоступен до окончания периода блокировки.

TC-003 Восстановление пароля через email

Модуль: Восстановление доступа
Приоритет: Высокий
Тип тестирования: Functional / Email flow

Предусловия:

* Пользователь зарегистрирован в системе.
* Email пользователя подтвержден.
* Почтовый сервис доступен.

Тестовые данные:

* Email: user@test.ru

Шаги:

1. Открыть страницу авторизации.
2. Нажать ссылку “Забыли пароль?”.
3. Проверить переход на страницу восстановления доступа.
4. Ввести email зарегистрированного пользователя.
5. Нажать кнопку отправки инструкции.
6. Проверить HTTP-ответ запроса восстановления.
7. Проверить получение письма на указанный email.
8. Открыть ссылку из письма.
9. Ввести новый пароль.
10. Подтвердить новый пароль.
11. Сохранить изменения.
12. Выполнить авторизацию с новым паролем.

Ожидаемый результат:

* Открывается страница восстановления доступа.
* Система принимает email зарегистрированного пользователя.
* Сервер возвращает успешный ответ.
* Пользователь получает письмо со ссылкой восстановления.
* Ссылка открывает страницу смены пароля.
* Новый пароль успешно сохраняется.
* Пользователь может авторизоваться с новым паролем.
* Старый пароль больше не подходит для входа.

TC-004 Проверка доступа к административному разделу без авторизации

Модуль: Авторизация / Контроль доступа
Приоритет: Критический
Тип тестирования: Security / Access control

Предусловия:

* Пользователь не авторизован.
* Административный раздел существует.
* URL административного раздела известен.

Тестовые данные:

* URL: /admin

Шаги:

1. Открыть браузер в режиме инкогнито.
2. Перейти напрямую по URL административного раздела.
3. Проверить HTTP-ответ сервера.
4. Проверить поведение интерфейса.
5. Повторить запрос через DevTools или Postman без токена авторизации.

Ожидаемый результат:

* Доступ к административному разделу не предоставляется.
* Пользователь перенаправляется на страницу авторизации или получает сообщение об отсутствии доступа.
* Сервер возвращает 401 Unauthorized или 403 Forbidden.
* Данные административного раздела не загружаются.
* API не возвращает защищенную информацию без токена авторизации.

TC-005 Завершение пользовательской сессии после выхода из системы

Модуль: Авторизация / Сессия
Приоритет: Высокий
Тип тестирования: Functional / Security

Предусловия:

* Пользователь успешно авторизован.
* Пользователь находится в личном кабинете.
* Активная сессия создана.

Тестовые данные:

* Логин: user@test.ru
* Пароль: User123!

Шаги:

1. Авторизоваться в системе.
2. Проверить наличие активной сессии или токена.
3. Нажать кнопку “Выйти”.
4. Проверить HTTP-ответ запроса выхода.
5. Проверить удаление токена из Cookie или Local Storage.
6. Обновить страницу браузера.
7. Попробовать перейти напрямую в личный кабинет.
8. Повторить защищенный API-запрос со старым токеном.

Ожидаемый результат:

* Сервер возвращает успешный ответ на запрос выхода.
* Пользователь выходит из системы.
* Токен авторизации удаляется или становится недействительным.
* После обновления страницы пользователь остается неавторизованным.
* При прямом переходе в личный кабинет пользователь перенаправляется на страницу входа.
* Старый токен не дает доступа к защищенным API-методам.
